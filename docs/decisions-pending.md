# Decisions to review

Non-obvious choices made during implementation, for the maintainers to confirm or change. Each entry says what was decided, why, and what changing it would cost. Settled decisions move to `spec.md` §15.

| # | Area | Decision | Why | Cost to change |
|---|---|---|---|---|
| 1 | Subscriptions | **The unsubscribe deferral applies only over emulation** (HTTP-streaming). Over WebSocket, `unsubscribe()` during a subscribe in flight sends the unsubscribe at once, and a later subscribe doesn't wait for its reply. The spec draft deferred on every transport. | Replaying the TLA+ traces showed the model (`Ordered`) doesn't allow deferring over WebSocket, and centrifuge-js (#443) doesn't defer there either. Same visible result, one fewer round trip. | Small: one condition in `sub.rs`, and the replay would flag the model mismatch. |
| 2 | Subscriptions | `unsubscribe()` while the flow waits for `get_token` / `get_state` **sends an unsubscribe command**. | centrifuge-js (`_inflight`) and the TLA+ model (`NeedsUnsubCmd`) do. Redundant (no subscribe was sent), but harmless, and keeps the server bookkeeping identical to the reference. | Small, but it diverges from the model: the replay test would need an exception. |
| 3 | Connection | **A disconnect push is honoured while connecting** (before the connect reply). | Found by the real-server tests: over HTTP-streaming Centrifugo reports a refused connect (invalid token, 3500) with a disconnect push then EOF, not a close code. Ignoring it made the client reconnect forever. Pinned by a core test and a fake-server test. | None; it's a bug fix. Worth a look at whether other SDKs have the same gap. |
| 4 | Transport | An HTTP-stream response with `Content-Type: text/html` (status 200) is a **transport failure** (captive portal), retried with fallback rules, not a protocol error. | Hotel and airport Wi-Fi answer every request with a login page. Treating it as bad protocol would stop the client for good. | Trivial. |
| 5 | Transport | HTTP-streaming uses **HTTP/1.1 only** (no HTTP/2 multiplexing). | One long-lived stream plus short emulation POSTs; HTTP/2 brings no benefit here, and avoiding it removes the `h2` dependency and ALPN edge cases with proxies. | Medium: add the `h2` feature to hyper and ALPN `h2`. |
| 6 | TLS | Certificates are verified **only through `rustls-platform-verifier`** (the OS trust store), with no `webpki-roots` fallback. | Matches what users expect from the OS (corporate CAs, revocation, user-installed roots). A minimal Linux container without `ca-certificates` fails to verify; `TlsConfig::add_root_pem` covers that. | Small: an optional `webpki-roots` feature. |
| 7 | Errors | Error events carry the cause as `Arc<dyn Error + Send + Sync>` (`ArcError`), so every event is `Clone`. | Events go to a handler and to streams; cloning must be cheap and always possible. | API change to `ClientError`/`SubscriptionError::source`. |
| 8 | Handlers | A **panicking handler** stops the client (`error(HandlerPanicked)`, then `disconnected`), but the rest of that batch's events are still delivered to their handlers. Its publication isn't committed. | Matches the core's "panic = no ack" rule (the position stays before the publication, so a reconnect redelivers it), while other handlers still see a consistent sequence. | Small, in `dispatch.rs`. |
| 9 | Lifecycle | **Operations after `close()` are dropped** at the handle (never reach the driver). | They can never be applied; sending them made waiters wait for a sequence number nobody applies (found by the tests: `publish` after `close` timed out instead of failing with `ClientClosed`). | None. |
| 10 | Lifecycle | `close().await` **inside an event handler returns at once** (the close still happens). | The close can't complete while the handler it was called from runs; waiting would deadlock (pattern 43). | None. |
| 11 | API | `Client::builder(url)` picks the transport from the scheme; a bad URL is reported by `build()`, not by `builder()`. | Builders stay infallible and chainable; every validation error comes from one place. | Small. |
| 12 | Emulation | Emulation POST status rules: **404, 401, 403, 3xx and 5xx close the transport** (state unknown, reconnect); any other non-2xx (e.g. 413) fails only that request's calls with `Error::Transport { status }`. | 404 means the session's node is gone; auth and redirects won't recover by retrying the same session; a too-large request is the caller's problem. | Small, in `http_stream.rs`. |
| 13 | Handles | A `Subscription` handle keeps its `Client` alive. | `sub.publish()` etc. need the connection; this is what users expect from centrifuge-js, where a subscription references its client. Dropping all `Client` handles while subscriptions are held doesn't close the connection. | Medium: weak references and a new error for "client dropped". |
| 14 | Testing | The TLA+ trace replay narrows the model's schedules (`tests/tla/Replay.tla`) to the ones this SDK implements: flows start in the enabling step once connected, queued deliveries before anything else, callbacks don't settle in the optimistic-subscribe window, no per-command write errors over WebSocket. | The core is eager where the model is non-deterministic; generating only the schedules the core can take makes every divergence a real one. `ss_store_unannounced` is unreachable under these schedules (server-side subscriptions are announced before the app can act). | Phase 3 (optimistic subscriptions) needs the third restriction lifted. |
| 15 | Connection | After a **system sleep longer than the no-ping window**, the client reconnects at once instead of waiting a full window on the old socket. | Found while checking the README against the code: after a long laptop sleep the client waited up to ping + max delay (~35 s by default) on a connection the server had dropped, or on a network that changed. A shorter sleep keeps the connection and only re-arms liveness. | Small (`on_resumed`). |
| 16 | Proxies | SOCKS5 with local DNS **tries every resolved address**, one SOCKS session each. | Found by the new proxy tests: `localhost` → `::1` first, which an IPv4-only server refuses through the proxy; a direct connection already tried every address. | None. |
| 17 | CI | Benchmark comparisons go to the job summary of a `pull_request` workflow, not a PR comment. | A comment needs a write token on PRs from forks (`pull_request_target`), which zizmor flags as dangerous; the summary needs no extra permissions. | Small: a commenting step with `pull_request_target`. |
